# BRAIN_INTELLIGENCE_ADDENDUM.md — Permanent EVOLIX Intelligence Contract

**Status:** Mandatory extension to `BRAIN.md`  
**Applies to:** Every EVOLIX Trade ERP module from project start  
**Audience:** Antigravity, Copilot, developers, reviewers, testers

---

# 1. Intelligence Is a Day-0 Design Constraint

EVOLIX must be built so that future reports, deterministic intelligence and conversational AI can reliably answer questions from authoritative ERP data.

This does **not** mean building AI into every module now.

It means every module must preserve:

- reliable historical facts;
- explicit statuses;
- business date and technical timestamps;
- company/branch/godown scope where applicable;
- source-document references;
- creator/poster/canceller identity where meaningful;
- immutable posted snapshots;
- reversal/cancellation lineage;
- Decimal-safe financial and quantity data;
- auditable configuration/rule decisions;
- stable service/API boundaries;
- drill-down from aggregate metric to source transactions.

---

# 2. Two Intelligence Layers

## 2.1 Engineering Intelligence

Before implementing any task, Antigravity must evaluate:

```text
Requirement
    ↓
Company / Branch / Godown Scope
    ↓
RBAC / Approval
    ↓
Accounting Impact
    ↓
Inventory Impact
    ↓
GST / Tax Impact
    ↓
Audit / Provenance
    ↓
Offline / Cloud Behavior
    ↓
Concurrency / Idempotency
    ↓
Migration / Existing Data
    ↓
Reporting / Drill-down
    ↓
Intelligence Readiness
    ↓
Automated Tests
    ↓
Small-Defect QA Sweep
    ↓
Manual User Verification
```

A screen is never considered the module.

The complete business capability is the module.

## 2.2 Business Intelligence

Business intelligence is initially deterministic and local-first.

It may include:

- metrics;
- comparisons;
- trends;
- thresholds;
- anomaly flags based on explicit rules;
- reorder suggestions;
- ageing/collection attention;
- margin analysis;
- stock velocity;
- product/customer/supplier performance;
- alerts;
- recommendations with explanations.

The calculation must be reproducible from authoritative ERP data.

---

# 3. Intelligence Must Never Become Transactional Authority

The Intelligence layer is read-only with respect to posted business truth.

It must never directly mutate:

- stock movement;
- accounting voucher;
- posted invoice;
- posted purchase;
- payment;
- GST snapshot;
- receivable/payable truth;
- posted return;
- financial-period state.

If intelligence recommends an action, it may create or prefill a **draft** through the normal domain workflow.

Example:

```text
Recommendation: Reorder 120 units
        ↓
User chooses Create Purchase Order Draft
        ↓
Normal Purchase Service validation / permissions / approval
        ↓
Draft Purchase Order
```

---

# 4. Explainability Rule

Never present an unexplained opaque score as business truth.

Bad:

```text
Customer Risk Score: 76
```

Preferred:

```text
COLLECTION ATTENTION
Customer: ABC Traders
Outstanding: ₹240,000
Overdue > 60 days: ₹110,000
Average payment delay: 21 days
Last payment: 43 days ago
Reason: overdue balance increased for three consecutive billing cycles.
```

Every insight must provide, where practical:

- metric definition;
- period/window;
- company/branch/godown scope;
- source count;
- reason/trigger;
- drill-down target;
- freshness/calculated-at timestamp.

---

# 5. No AI Dependency in Core ERP

Core ERP must work without AI and without internet.

V1 intelligence should prefer:

```text
PostgreSQL
Python Decimal
FastAPI services
SQLAlchemy queries
scheduled/local worker jobs
explicit formulas
configured thresholds
```

Do not require an external LLM for:

- invoice posting;
- accounting;
- stock;
- GST calculation;
- payment allocation;
- basic reporting;
- deterministic intelligence.

---

# 6. Future Conversational AI Contract

A future AI assistant is a **client of EVOLIX services**, not a database superuser.

Forbidden:

- arbitrary SQL generated by LLM;
- direct unrestricted ORM access;
- bypassing permissions;
- bypassing company/branch scope;
- inventing report totals;
- allowing AI output to become ledger/stock truth;
- silent high-risk actions.

Required path:

```text
User message
  ↓
Authenticated channel identity
  ↓
Conversation context
  ↓
Intent / tool selection
  ↓
RBAC + company/branch scope
  ↓
Typed EVOLIX Tool
  ↓
Domain / Report / Intelligence Service
  ↓
Authoritative result
  ↓
Natural-language explanation / table / chart / PDF
```

---

# 7. Report/PDF Rule

The AI assistant never calculates official report totals itself.

It converts natural language into a typed report request.

Example:

```text
User: September top 20 customers ka sales, profit aur outstanding PDF do.
```

becomes conceptually:

```text
report_type: CUSTOMER_PERFORMANCE
period: 2026-09-01..2026-09-30
columns: sales, gross_profit, outstanding
sort: sales desc
limit: 20
output: PDF
```

Then the normal report service calculates values and the document/report renderer generates the PDF.

---

# 8. Multilingual Rule

Business logic remains language-independent.

The future assistant may accept:

- English;
- Hindi;
- Hinglish;
- Gujarati and other supported languages later.

Natural language is translated into typed intent/parameters. Domain calculations remain identical.

Do not store separate financial logic per language.

---

# 9. Drill-down Rule

Every management metric should be designed to drill down to the records that produced it.

Examples:

- Sales → invoice list;
- Gross Profit → invoice/item profitability detail;
- Stock Value → item/godown/batch balances and movements;
- Outstanding → bill allocations/receipts;
- Reorder suggestion → stock + sales history + pending purchase/sales orders;
- Return rate → source sales/returns.

If a metric cannot be explained or reconciled to source records, it is not production-ready.
